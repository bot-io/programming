Three fixes applied:

### 1. Gemini temperature 1.0 → 0.2 (Worker)
Temperature 1.0 is for **creative writing**, not translation. At that setting, Gemini 3.5 Flash with thinking can "go creative" and generate entirely new English text instead of translating to Spanish. Lowered to 0.2 — standard for translation tasks.

Also reduced thinking budget 2048 → 1024 (translation doesn't need deep reasoning).

### 2. Explicit translate instruction in user text (Worker)
The system prompt alone wasn't enough. Now every user message starts with:
```
Translate the following text to Spanish. Output ONLY the translation, nothing else.
```
This makes the instruction unmissable, even at the model level.

### 3. Removed context prefix from app requests
The app was prepending "Previous context (do NOT translate, use only for understanding)" with Spanish text **into the text field** sent to the model. This mixed Spanish + English in the user message, which at temperature 1.0 caused the model to:
- See the Spanish context and think it should generate creative writing
- Get confused about what to translate vs. what's context

Now the app sends **only the text to translate** — clean, unambiguous.

**Important:** Clear translations from Settings before re-translating, since the old bad results may be cached in both the D1 cloud cache and the local app database.
