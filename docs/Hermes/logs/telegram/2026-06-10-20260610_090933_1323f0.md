## How the Translation Worker Works

### Architecture

```
📱 Android App
    │
    │  POST /translate/batch  (OkHttp, 120s timeout)
    │  { pages: [{index, text}], source_lang, target_lang }
    │
    ▼
🌐 Cloudflare Worker  (dual-reader-translate.dualreader.workers.dev)
    │
    ├─ 1️⃣ Gemini 3.5 Flash (thinking=2048, 25s timeout)
    │      ↓ on failure
    ├─ 2️⃣ Gemini 2.5 Flash (10s timeout)
    │      ↓ on failure
    └─ 3️⃣ GLM-4.7-Flash via open.bigmodel.cn (20s timeout, thinking disabled)
           ↓ on failure
        502 error → app falls back to ML Kit (on-device)
```

**Key design decisions:**
- **API keys never leave the server** — stored as CF Worker secrets, APK has zero credentials
- **3-tier fallback chain** — best model first, each with its own timeout
- **Batch endpoint** — up to 3 pages / 10,000 chars per call, reducing round-trips
- **Rate limiting** — 3s cooldown between requests, 500 req/IP/day, enforced via CF Cache API
- **Free tier** — Worker (100K req/day free), Gemini (250 RPD free), GLM (unlimited free)
- **Zero infrastructure** — no servers, no databases, no containers

### Request Flow

1. App groups up to 3 consecutive uncached pages into a batch
2. Calls `POST /translate/batch` with page indices + text
3. Worker formats a Bulgarian-specific literary translation prompt with context from previous pages
4. Tries Gemini 3.5 Flash with thinking mode (best quality for literary text)
5. On failure → Gemini 2.5 Flash (faster, still good)
6. On failure → GLM-4.7-Flash (free unlimited, no thinking to save tokens)
7. Returns `{ translations: [{index, text, model}], provider }`
8. App caches translation per-page per-language in Room DB + stores which model was used

## Scaling for Play Store

### Current Limits (Single User)

| Resource | Free Tier | Limit |
|---|---|---|
| CF Workers | 100K req/day | More than enough for 1 user |
| Gemini 3.5 Flash | 250 req/day | **Bottleneck** |
| Gemini 2.5 Flash | 250 req/day | Shared with 3.5 |
| GLM-4.7-Flash | Unlimited | Backup only |

For **one user** reading a 300-page book: ~100 batch calls → fits in Gemini's 250 RPD. Fine.

### Scaling to 100+ Users

The fundamental problem: **Gemini free tier is shared across ALL users**. 250 RPD total. Here's the scaling roadmap:

#### Phase 1: Multi-Key Pool (next step, no cost)
```
Worker rotates through N Gemini API keys:
  keys = [env.GEMINI_KEY_1, env.GEMINI_KEY_2, ..., env.GEMINI_KEY_N]
  pick = hash(clientIp + date) % keys.length
```
- Each additional key = +250 RPD
- 10 keys = 2,500 RPD ≈ ~25 concurrent users translating books daily
- **Cost: $0** — just create more Google AI Studio accounts
- Implementation: ~20 lines in the Worker

#### Phase 2: Upgrade to Gemini Paid ($0.075/1M chars)
- **Removes the 250 RPD limit entirely**
- 1M chars ≈ ~3,000 pages of text = ~1,000 batch calls
- 100 users each translating 1 book/day ≈ ~$7.50/month
- **Cost: ~$7.50/mo for 100 users**
- Just set billing in Google AI Studio, no code changes

#### Phase 3: Smart Caching Layer (CF KV or D1)
```
Worker checks KV cache: hash(sourceText + targetLang) → translation
  Hit → return cached (0 API cost)
  Miss → translate + store in KV
```
- Many users translate the **same popular books** (e.g. Harry Potter in Bulgarian)
- Cache hit rate for popular titles: 80%+
- **CF KV free tier**: 100K reads/day, 1K writes/day
- **CF D1 free tier**: 5M reads/day, 100K writes/day (better for structured data)
- Implementation: ~50 lines in Worker

#### Phase 4: Usage-Based Quotas
- Anonymous: 50 pages/day free (enough to try the app)
- Registered: unlimited (requires Play Store purchase or subscription)
- Track per-device via `Installation ID` (UUID generated on first install)
- Store in CF D1: `{installId, date, pageCount}`
- Implementation: new `/quota` endpoint in Worker + app-side quota checks

#### Phase 5: Regional Edge Optimization
```
CF automatically routes to nearest edge:
  EU user → EU CF PoP → Gemini EU endpoint
  US user → US CF PoP → Gemini US endpoint
```
- Already happens automatically with CF Workers
- Can add regional Gemini endpoints for lower latency
